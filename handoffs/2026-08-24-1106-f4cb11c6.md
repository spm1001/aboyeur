### Reflection

Three write faults in one session, all mine, all in the same family — **prose and data pushed through a shell**:

1. `bon show --json | .get('how')` returned empty because the brief lives under `brief.how`. The concatenation became just the correction and `bon edit` **replaced 2,812 characters**. Recovered from git. Filed as `bon-rokita`.
2. Filing `carte-jisehu`, backticks inside a double-quoted `--how` ran as command substitution and spliced an empty result into its own text. Repaired via subprocess.
3. Both are the estate's existing ssh-probe rule (base64-armour the payload) generalised: **any long prose argument through a shell wants a heredoc or a subprocess list, never an interpolated double-quoted string.**

What actually caught things was reading output rather than exit codes. A compound `ssh ... uninstall` **exited 0** with the Mac half timed out inside it. And I wrote `git fetch … | head -5 && echo "FETCH OK"` — the `&&` chained off `head`, printing OK over a failed fetch, then a divergence count against a stale ref. Both are traps.md rows I walked into anyway.

## For Claudes to come

**A retirement is not finished when the code is deleted — it is finished when nothing still *instructs* a reader to use the thing.** Deleting sonnette took one commit. Making the estate honest about it took seven more, across five repos: the suite shard, the brigade registry that generates the docs site, a lint's repo map, a sibling skill's integration list, a shell wrapper still launching at the corpse, the always-loaded vocabulary row, and a traps row keyed on the dead transport's name. None of those would have failed loudly. The discriminating question at the end of any removal is not "is the code gone" but "what would a fresh session still be told to do", and the cheap instrument is a single estate-wide grep for the dead name, run *after* the deletion, with every surviving hit forced to justify itself as a dated record.

**And the corollary that cost the most here: check whether the work is already tracked before improvising a plan for it.** I surveyed this board with `bon list | head -40` and missed `aby-dunudo` — the outcome that green-lit this exact retirement on 2026-08-09 — because it sat below the cut. It carried two facts I then got wrong by re-deriving them: that `ssh <host> sonner <repo>` preserves cross-machine reach (I told Sameer the capability was lost and wrote that into four files), and that `MESH-SETUP.md` should be kept as historical (I deleted it). The improvised plan matched `aby-dunudo`'s `--what` almost step for step, which is luck, not method — and luck is exactly what makes this worth writing down, because nothing in the session would otherwise have exposed the gap. A truncated board is the same fault as a truncated search result, and worse in one respect: a search tool usually prints its match count beside the preview, so the discriminator is in the output, whereas piping a board through `head` destroys that possibility *after* the tool has finished being honest. Filed as `carte-jisehu` against `verification.md`.
